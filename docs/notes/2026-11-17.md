## Задания из открытых источников — исследование и план (ничего не сгенерировано и не импортировано)

Вопрос пользователя: «Сможешь добавить с открытых источников ещё задания, для каждого уровня?» Уточнение: «чтобы эти задания в списке на сайте были в самом конце списка».
Ответ: да, с оговорками (ниже). Ждём решений пользователя и «ок» на пилот (правило 1).

### Как устроен контент сейчас
- `content/n5.json … n1.json` — 302 текста: N5 60, N4 60, N3 61, N2 61, N1 60; по 12 на категорию (`short`/`medium`/`long`/`info_search`/`article`, у N3/N2 по 13 `article`). `source_type`: `original` и `news_adapted` (N3–N1), `jlpt_official` — ни одного.
- `validate_content.py` проверяет схему и **точную инвентаризацию** (`EXPECTED_INVENTORY`: 12 текстов на категорию и число вопросов). Добавить тексты в `content/nX.json` нельзя — `content_loader.load_content()` упадёт на валидаторе (`sys.exit(1)`). Валидатор берёт все `content/*.json` (кроме `difficulty_bands.json`) — новый файл в корне `content/` тоже сломает инвентаризацию; подпапка не попадёт.
- `content_loader.load_content()`: при `levels_to_replace` удаляет все тексты уровня вместе со слотами, попытками и состояниями пользователей; без него — upsert по `slug`, но для существующего текста удаляет и пересоздаёт вопросы (новые id вариантов → ломаются токены/попытки, затираются правки из админки I30). **Для прода не годится.**
- `seed.py`: при ≥250 текстах — «Skipping mass generation». Прод (Neon) засеян 302 текстами при первом старте.
- `main.py` lifespan при каждом старте: `seed_database()` → `tools/migrations/add_stream_tables.migrate()` — пересчитывает `content_hash` и `profile_key` для всех текстов, `origin` ставит `archive`, только если пусто (новый `origin` сохранится).
- Модель `Text`: `slug` (unique), `origin` (archive/ai_generated/parametric/pdf_import), `verification_status`, `profile_key`, `source_exam` (показывается бейджем в окне задания, `exercise_view.js:66,106`), `is_active`. Отдельного поля атрибуции нет.
- Разметка: фуригана — janome в `app/services/passage_markup.py` (как в редакторе I30, `図書館《としょかん》`, `[ev-q1]…[/ev-q1]`), чтения проверяются вручную, `needs_manual_review` для спорных.
- Бейдж происхождения: `stream_slots.js:31–40`, всё «прочее» → «📜 JLPT 過去問». Это уже сейчас неверно для всех 302 текстов → **I33** (записан, не исправлен).

### «В самом конце списка» — что это значит в коде
- Публичного списка всех заданий на сайте нет: пользователь видит 3 слота на уровень/категорию (`pick_next`: сначала точное совпадение `profile_key`, потом любой текст уровня/категории, оба — `ORDER BY random()`) и архив решённых (по дате решения). `/api/texts` клиентом не вызывается.
- Список всех заданий есть только в `/admin` → `ORDER BY id`: новые тексты получат большие id и будут в конце автоматически.
- В потоке «в конце» без правки кода не гарантируется: новый текст с «дефолтным» `profile_key` выпадет раньше старых, у которых ключ не дефолтный (например, у всех N1 и большинства N2 ключ не дефолтный — они идут только через запасной путь). Чтобы новые шли после старых, нужна правка `pick_next`: сначала старые, новые — когда старые в этой категории решены.

### Путь на прод (предложение)
- Новые тексты — в отдельной папке `content/open/n5.json … n1.json` (валидатор основной инвентаризации их не видит), slug вида `n4-open-short-001`.
- Новый идемпотентный импорт «только вставить отсутствующие по `slug`» (никогда не обновлять и не удалять), с той же проверкой схемы записей; вызывать при старте после `seed_database()` → тексты попадут в Neon сами при деплое. Повторный деплой ничего не дублирует; правки из админки не затираются.
- `origin = "open_source"` (новое значение), `verification_status` — `expert_reviewed` только после проверки `@jlpt-expert`, иначе `unverified`.
- Бэкап Neon перед первым деплоем (ветка Neon или `pg_dump`) — делает пользователь.
