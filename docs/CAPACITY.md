# 📊 Модель вместимости и бюджетов ресурсов (Capacity Plan)

Документ описывает математический расчёт ресурсов Dokkai для обеспечения работы в рамках $0 бесплатной инфраструктуры:
- **Оперативная память (Render):** потолок 512 MB.
- **Хранилище базы данных (Neon Postgres):** проектный потолок 500 MB (при квоте Neon 1 GB).
- **Сетевой трафик:** потолок 5 GB/мес.
- **Локальное хранилище браузера (IndexedDB):** до 50–250 MB на устройство.

---

## 1. Бюджет оперативной памяти (RAM 512 MB)

### Фактические замеры процесса FastAPI + pykakasi:
- **Базовый рантайм Python 3.11:** ~22.8 MB
- **Импорт pykakasi:** ~36.7 MB
- **Инициализация словарей pykakasi:** ~132.9 MB
- **Полная загрузка FastAPI + SQLite/Postgres ORM + моделей:** **~179.8 MB** (Private Memory: ~158.9 MB)

### Распределение доступных 512 MB:
```text
┌──────────────────────────────────────────────────────────────┐
│ [███████████████▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒] │
│   App Core: 180 MB (35%)     │   Свободный запас: 332 MB (65%)│
└──────────────────────────────────────────────────────────────┘
```
- **Пул соединений к базе (asyncpg / psycopg2):** до 5 соединений $\times$ 4 MB = 20 MB.
- **Обработка одновременных HTTP-запросов:** 10 одновременных соединений $\times$ 1.5 MB = 15 MB.
- **Пиковое потребление под нагрузкой:** ~220–250 MB.
- **Запас прочности до лимита OOM (512 MB):** **>260 MB (более 50% запаса)**.

## 2. Бюджет хранилища базы данных (Neon Serverless Postgres)

### Разделение данных: Сервер vs Клиент (Local-First)
Чтобы база данных не раздувалась, на сервере **строго запрещено хранить**:
1. Развёрнутые ответы пользователя на каждый вопрос (`selected_option_id`, `is_correct`).
2. Персональные текстовые заметки и переводы.
3. Избранные списки текстов и слов.
4. Промежуточные черновики прохождения Wizard.

Все эти данные сохраняются исключительно в браузере пользователя через **IndexedDB**.

### Серверная модель данных и расчёт байтов на запись:

| Таблица / Данные | Поля | Размер 1 записи (байт) |
| :--- | :--- | :--- |
| `users` | `id` (UUID), `provider`, `provider_sub`, `nickname` (VARCHAR 32), `avatar_url`, `timezone` (VARCHAR 32), `xp` (INT), `streak` (SMALLINT), `max_streak`, `last_study_date` (DATE), `badges_bitmask` (BIGINT), `flags` (opt-in) | ~280–320 байт |
| `user_completions` (компактная) | `user_id` (UUID), `text_id` (INT), `completed_at` (TIMESTAMP), `score` (SMALLINT), `points` (SMALLINT), `seconds` (INT) | ~32 байта |
| `catalog_texts` (каталог заданий) | ~100–150 эталонных текстов JLPT N5–N1 с вопросами и переводами | Всего ~8–12 MB фикс. |
| Индексы PostgreSQL (B-Tree) | Индексы по `user_id`, `(provider, provider_sub)`, `(xp DESC)` | ~20% от объёма данных |

### Расчёт вместимости пользователей при проектном лимите 500 MB:

- Фиксированный объём (каталог заданий + системные таблицы Postgres): ~15 MB.
- Доступно для пользовательских данных: $500\text{ MB} - 15\text{ MB} = 485\text{ MB} = 485\,000\text{ KB}$.
- Допустим, средний активный пользователь проходит **100 заданий**:
  - Запись профиля: 0.3 KB
  - 100 записей завершений: $100 \times 0.032\text{ KB} = 3.2\text{ KB}$
  - Накладные расходы индексов: $0.7\text{ KB}$
  - **Итого на 1 пользователя на сервере:** $\approx 4.2\text{ KB}$.

$$\text{Вместимость активных пользователей} = \frac{485\,000\text{ KB}}{4.2\text{ KB}} \approx \mathbf{115\,476\text{ пользователей}}$$

При более лёгком профиле (20 решённых заданий) вместимость превышает **350 000 пользователей**.

## 3. Пороговые уровни защиты и поведение при исчерпании (Degradation Policy)

| Порог заполнения | Объём БД (из 500 MB) | Системное действие | Реакция UI |
| :--- | :--- | :--- | :--- |
| **Норма (< 70%)** | < 350 MB | Все операции активны. | Штатный режим работы. |
| **Алерт (70% – 85%)** | 350 MB – 425 MB | Эндпоинт `/api/health` сигнализирует `storage_warning: true`. Логируется предупреждение. | Пользователи работают без ограничений. Администратор видит предупреждение в логах. |
| **Мягкий стоп (85% – 95%)** | 425 MB – 475 MB | **Мягкий запрет новых регистраций** (`status: 503 Service Unavailable` с кодом `SIGNUPS_PAUSED`). Существующие пользователи продолжают заниматься. | Баннер при попытке новой регистрации: *«Регистрация новых участников временно приостановлена из-за лимита хранилища. Гостевой режим доступен полностью офлайн.»* |
| **Аварийный режим (> 95%)** | > 475 MB | Переключение сервера в **Read-Only**: начисление XP/streak сохраняется локально в IndexedDB в очередь синхронизации. | Баннер: *«Синхронизация прогресса временно отложена. Ваш прогресс сохраняется на устройстве и обновится автоматически.»* |

## 4. Локальный бюджет устройства (IndexedDB)

- Браузеры (Chrome, Safari, Firefox) выделяют до **50 MB** без дополнительных разрешений (и до 20% свободного диска при необходимости).
- Dokkai использует базу `IndexedDB` с именем `dokkai_local_v1`.
- Структура хранилища:
  1. `history`: полная история каждого вопроса с выбранными ответами и таймингами (500 байт/вопрос $\approx$ 50 KB на 100 вопросов).
  2. `notes`: личные заметки пользователя по грамматике и лексике.
  3. `favorites`: сохранённые в закладки материалы.
  4. `offline_tasks`: кэшированные карточки заданий для тренировки в метро/самолёте.
- В интерфейсе предусмотрена кнопка **«Экспорт данных (JSON)»** и **«Импорт данных»**, что гарантирует сохранность прогресса пользователя даже при очистке кэша браузера или смене телефона.
